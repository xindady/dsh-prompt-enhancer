# dsh-prompt-enhancer

一键「增强提示词」插件。

在输入框工具栏右侧（模型选择器旁边）添加一个 **✦** 图标按钮：点击后把当前
草稿发给 Host 半的增强路由，用双模板（system + user）通过 Harness LLM 服务重写，再把
结果写回草稿。**@文件引用逐字保留，写回过程可撤回。**

**输入框为空时不显示图标**，开始输入后才出现。

## 交互

按钮是同一个位置的三态切换：

| 状态 | 外观 | 行为 |
|---|---|---|
| 待优化（默认） | ✦ 星形图标 | 悬停有底色，点击开始优化；**草稿为空时整个按钮不渲染** |
| 优化中 | 旋转加载环 | 禁用，防重复点击 |
| 可撤回 | ↺ +「撤回」 | 点击恢复原提示词，回到 ✦ 态 |

优化完成后若手动改动草稿，撤回态自动退回 ✦（此时撤回已无意义）。清空草稿后回到不显示状态。

## 安装

### 方式一：Plugin Manager（推荐）

把本目录作为本地包安装到当前 profile：

```
plugin_manager { "action": "install_bundle", "target": "<本目录绝对路径>" }
```

安装后在 **侧边栏 → 插件** 页可以看到「提示词增强」卡片（含图标与中英文说明），可随时启停。
新装 bundle 通常经 HMR 即时生效；若替换已有包，需要重启进程加载新的 JS 模块。

### 方式二：手工挂载

profile（`$DSH_HOME/profiles/<name>`）下：

1. 让包可从 profile 解析，例如 `pnpm add link:<本目录绝对路径>`；
2. 在 profile 的 `cordis.patch.yml` 追加：

```yaml
- insert:
    - id: prompt-enhancer
      name: 'dsh-prompt-enhancer'
```

## 工作方式

- **双模板**：system 消息负责角色设定、分析流程与硬约束；user 消息承载用户原文与增量要求。
- **分析流程**：识别主要目标 → 标注歧义与缺口 → 评估指令清晰度 → 检查缺失上下文 →
  套用提示工程原则（清晰具体、补齐上下文、显式参数与约束、结构化输出、相关示例、
  语气匹配、删冗余）→ 生成增强版。
- **五条约束**：不主动索要指南/教程、不索要代码片段、不擅自指定技术栈、只讲 WHAT 不讲 HOW、
  不回答问题而是把问题扩写得更详细。
- **两条最高优先级**：输出语言与用户输入完全一致且不出现语言标注；结果保持简洁（约 800 字符内）。
- **结果清洗**：`trim()` 后去除首尾成对引号（含中英文弯引号）。
- **引用审计**：Host 与浏览器两侧各自校验原草稿中每个 `@token` 在结果里逐字存在；Host 侧
  失败会带修复指令自动重试一次，浏览器侧失败直接拒绝写回（原文不动）。

## 写回与撤销

| 草稿形态 | 写回方式 | 撤销 |
|---|---|---|
| 无 @引用 chip | `inputActions.insertText` 整篇替换（一次编辑事务） | 点「撤回」或 Ctrl+Z |
| 含 @引用 chip | 保留 chip 节点，仅重写 chip 之外的文本段 | 点「撤回」 |

`@` 引用 chip 在编辑器里是原子节点，纯文本插入无法重建，因此含 chip 时走分段写回；两种情况
都提供同一个「撤回」按钮恢复原草稿。

## 路由

`POST /plugins/prompt-enhancer/enhance`（同源，仅本机回环可访问）

```json
{ "text": "草稿原文", "sessionId": "可选" }
→ { "ok": true, "text": "增强后", "model": "provider/model", "elapsedMs": 1234 }
→ { "ok": false, "error": "...", "code": "..." }
```

模型路由解析顺序：插件 `config.provider/model` → 会话当前模型 → 部署默认模型
（`agentDefaultModel` 服务）。都取不到才报 `no_route`。

## 文件

| 文件 | 职责 |
|---|---|
| `index.js` | Host 半：模板、引用审计、`ctx.llm.stream` 调用、webServer 路由 |
| `client.js` | Client 半：工具栏图标按钮、草稿读写、撤回 |
| `cordis.patch.yml` | bundle patch（insert 一行） |
| `icon.svg` / `locale/*.json` | 插件管理页的图标与中英文标题描述 |

## 已知边界

- 新会话首屏（尚无消息、输入框处于 hero 态）不渲染该工具栏槽位，发过一轮消息后按钮常驻。
- 若在模型选择器临时切到别的模型，增强仍按部署默认路由执行（会话路由采集尚未接入）。
